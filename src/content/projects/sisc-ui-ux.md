## The process I am setting up

The division hands its designs to the association's front-end team. The
process is built around that handover, so that the team building a page
never has to guess what the design meant.

1. **One brief per request.** Every request arrives in one shared place, with
   the page, its goal, who it is for and the deadline. Requests do not arrive
   as private messages.
2. **One shared Figma library.** Colours, type sizes and spacing are Figma
   variables, and every component is drawn in all its states: hover, focus,
   disabled and error. The front-end team builds each piece once, and every
   site uses the same pieces.
3. **A review before handover.** A second designer checks the file against a
   short list: text contrast, touch targets of at least 44 px, every state
   drawn, and a phone frame next to the desktop one.
4. **A handover in Dev Mode.** A file is marked ready only when its layers are
   named like the components in the code, so values are copied, not guessed.
5. **A check after the build.** The designer compares the built page with the
   file at two screen widths before it goes live. Differences go back as
   tickets, not chat messages.

## Rebuilding the sites

The association's websites are rebuilt after the shared library exists, one
at a time and from the same pieces, so they do not drift apart again.
